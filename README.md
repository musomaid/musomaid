I build small but useful software experiments for healthcare operations: tools that reduce friction, improve clarity, and support safer day-to-day workflows.

My long-term interest sits at the intersection of medicine, AI, secure engineering, and clinical workflow automation—always with practical utility as the priority.

## `mission`

Healthcare operations still rely on messy notes, manual handoffs, disconnected tools, and fragile data handling. These gaps create avoidable risk and operational drag.

MUSOMA exists to build focused, practical tools that strengthen clarity, security, and flow across real clinical and operational environments.

> I care less about building flashy demos and more about building tools that can survive real workflows.

## `build_log` / `featured_projects`

### `clinical-notes-ai`
- **Description:** AI-assisted tool for transforming messy clinical text into cleaner structured notes.
- **Status:** Prototype
- **Stack:** Python, FastAPI, PostgreSQL
- **Focus:** summarization, structured output, documentation flow
- **Why it exists:** to reduce writing overhead while preserving useful clinical context.

### `medflow-dashboard`
- **Description:** Operational dashboard concept for monitoring queues, tasks, and clinical workflow signals.
- **Status:** Planning
- **Stack:** TypeScript, Node.js, PostgreSQL
- **Focus:** visibility, operations, internal dashboards
- **Why it exists:** to expose bottlenecks early and improve response timing.

### `secure-med-api`
- **Description:** Secure API starter for health-related applications with authentication, audit logs, and safe defaults.
- **Status:** Building
- **Stack:** FastAPI, PostgreSQL, Docker
- **Focus:** access control, logging, secure architecture
- **Why it exists:** to provide a reliable backend baseline for sensitive workflows.

### `health-data-utils`
- **Description:** Small utilities for cleaning, validating, and anonymizing health-related datasets.
- **Status:** Experimental
- **Stack:** Python, Pandas, Markdown
- **Focus:** data quality, anonymization, reproducible workflows
- **Why it exists:** to make operational data safer and easier to trust.

### `medical-ai-notes`
- **Description:** Public learning notes on healthcare AI concepts, prompts, safety, and evaluation.
- **Status:** Learning
- **Stack:** Markdown, Python
- **Focus:** learning in public, documentation, evaluation thinking
- **Why it exists:** to build consistent understanding and transparent decision-making.

### `audit-log-template`
- **Description:** Minimal audit logging pattern for backend applications that handle sensitive workflows.
- **Status:** Concept
- **Stack:** Python, FastAPI, PostgreSQL
- **Focus:** traceability, accountability, backend safety
- **Why it exists:** to standardize event tracking for defensible system behavior.
